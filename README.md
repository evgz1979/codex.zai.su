# Codex Z AI

Локальный персональный чат с установленным Codex. React + TypeScript + Vite,
backend на Node.js + TypeScript без runtime-зависимостей. Самостоятельный проект,
не связан с Actu и lighnode.

## Быстрый запуск

Нужны Node.js **22.16+ (ветка 22)**, npm и установленный Codex с активным входом:

```bash
codex --version
codex login status
# Только если вход ещё не выполнен:
codex login
```

На текущем Mac Node.js 22 установлен локально в `.tools/node` (игнорируется Git),
скрипты автоматически добавляют его в PATH. Системные настройки не меняются.
На другой машине установите Node.js 22 с https://nodejs.org/en/download.

```bash
cd /Users/evgz/Documents/codex.zai.su
bash scripts/npm.sh ci
bash scripts/npm.sh run build
bash scripts/start.sh
```

Открыть **http://127.0.0.1:3001** в обычном браузере. Этот один процесс обслуживает
собранный frontend и API. Для остановки нажать **Ctrl+C** в том же Terminal
или выполнить `bash scripts/stop.sh` из папки проекта. Скрипт сверяет ID
запущенного экземпляра перед отправкой SIGTERM и не останавливает чужой сервис.
При остановке прерывается текущий ответ и закрывается дочерний App Server.
При следующем запуске диалоги доступны в боковом списке.

Для разработки с автоматическим обновлением:

```bash
bash scripts/npm.sh run dev
```

Frontend: http://127.0.0.1:5173, backend: http://127.0.0.1:3001.
Ctrl+C останавливает оба сервера. После правок для обычного запуска повторить
`bash scripts/npm.sh run build`.

Если Node/npm уже в PATH, эквивалентные команды: `npm ci`, `npm run build`,
`npm start` и `npm run dev`. Скрипты `.sh` дополнительно находят Codex внутри
приложений Codex/ChatGPT на macOS, когда его нет в PATH.

## Launcher

`launcher.json` регистрирует проект в существующем пользовательском Launcher.
После обновления списка проектов выбрать **Codex Z AI → Локальный чат → Start**.
Автозапуск выключен. Остановка — Stop в Launcher. Перед первым запуском нужна
сборка, как описано выше. Не запускайте одновременно экземпляр из Terminal и
Launcher: приложение сообщит о занятом порте.

## Возможности

- Реальные ответы Codex по частям, новый диалог, список и продолжение истории.
- Состояния готовности, размышления, выполнения действия и ошибки.
- Остановка текущего ответа; закрытие вкладки не останавливает ответ.
- Технические события и вывод команд — в сворачиваемом блоке; до 100 событий,
  до 32000 символов в выводе каждого. Полный источник истории остаётся у Codex.
- Последние 50 ходов при открытии, кнопка загрузки более ранних сообщений.
- Адаптивный интерфейс для узких экранов. На компьютере Enter отправляет,
  Shift+Enter переносит строку; на сенсорном устройстве Enter переносит строку.
- `backend/src/memory.ts` — пустой интерфейс будущей персональной памяти.
  Автоматическое извлечение воспоминаний и векторная БД не реализованы.

## Архитектура и данные

```text
Браузер → HTTP/SSE → backend → stdio JSON-RPC → codex app-server → Codex
```

Официальный протокол: https://learn.chatgpt.com/docs/app-server.
Handshake `initialize`/`initialized`, методы `thread/start`, `thread/resume`,
`thread/turns/list`, `turn/start`, `turn/interrupt`; уведомления
`item/agentMessage/delta`, `item/started`, `item/completed`, `turn/completed`.
Проверено с `codex-cli 0.166.0-alpha.6`. App Server развивается, при обновлении
CLI нужно повторить live-проверку. Генерация схем установленной версии:

```bash
codex app-server generate-ts --out /tmp/codex-zai-protocol
```

`frontend/` — интерфейс; `backend/` — API, процесс Codex и адаптер событий;
`shared/` — DTO; `scripts/` — запуск и проверки; `deploy/` — заметки для Ubuntu.
Историю и контекст хранит сам Codex в своём пользовательском каталоге
(обычно `~/.codex`, с учётом `CODEX_HOME`). Приложение не читает файлы
авторизации: ими управляет Codex. `.local/conversations.json` хранит ID,
название и время диалогов этого приложения. `.local/workspace` — рабочая папка
read-only диалогов. В браузере сохраняется только ID выбранного диалога.
Индекс и данные Codex нужны для восстановления после перезапуска; не удаляйте их.
Это личные незашифрованные локальные данные, они не отправляются в GitHub.

## Настройки и безопасность

При необходимости скопируйте `.env.example` в `.env`. API-ключи не нужны:
используется существующий вход Codex. `CODEX_BIN` задаёт путь к CLI,
`CODEX_MODEL` — доступную аккаунту модель (по умолчанию настройки установленного
Codex), `DATA_DIR` — папку индекса. `PORT` — порт обычного сервера.
В dev proxy Vite настроен на 3001: при смене порта согласуйте его конфигурацию.

- Серверы привязаны к `127.0.0.1`. API проверяет Host/Origin, отклоняет cross-site
  запросы и требует JSON для POST. Это локальное однопользовательское приложение.
- Браузер получает только ограниченные API чата, без shell/RPC-прокси.
- На запуске, resume и каждом ходе закреплены read-only и `on-request` с
  пользователем как reviewer. Ответ App Server проверяется: при иной политике
  диалог блокируется. Сеть для команд запрещена; соединение Codex с моделью нужно.
- Расширение прав, изменения файлов и неподдерживаемые интерактивные запросы
  отклоняются с объяснением. Веб-интерфейс выдачи дополнительных прав не реализован.
- Подключённые приложения, плагины, browser/computer use, MCP-серверы, веб-поиск,
  hooks и multi-agent отключены для этого процесса Codex. Активный MCP-инвентарь
  проверяется при создании и восстановлении диалога. Пользовательский config и
  вход не изменяются.
- Секреты, `.env`, `.local`, `.tools`, БД, сессии и логи исключены из Git.
  Не вводите секреты в сообщения: текст диалога сохраняется Codex.
- Основное приложение остаётся локальным. Задание №2 размещает только отдельную
  статическую тестовую страницу на VPS: см. `deploy/https-test/README.md`.
  Публичный доступ к самому приложению — отдельный этап. VPN не изменяется.

На iPhone интерфейс адаптивный, но loopback MacBook недоступен с другого
устройства. Доступ с телефона по сети требует отдельного задания на безопасный
доступ; текущий MVP предназначен для браузера на MacBook.

## Проверки

```bash
bash scripts/npm.sh test
bash scripts/npm.sh run typecheck
bash scripts/npm.sh run build
# При работающем backend: создаёт настоящий тестовый диалог, расходует лимит Codex
bash scripts/npm.sh run test:live
# Остановить и снова запустить backend, затем проверить сохранённый контекст:
bash scripts/npm.sh run test:live -- resume
```

Live-проверка использует случайное кодовое слово и сохраняет ID тестового диалога
в игнорируемой `.local/live-test.json`. Фиктивного сервера или подмены ответов нет.
Unit-тесты проверяют сборку потоковых сообщений, отмену, вывод команд,
Host/Origin и восстановление индекса.

## Диагностика и ограничения

`GET /api/health` возвращает состояние подключения без сведений аккаунта и токенов.
При отсутствии авторизации выполните `codex login` в Terminal и перезапустите
приложение. При ошибке модели, сети или лимита сообщение Codex видно в чате.
При падении App Server перезапустите backend и откройте диалог снова; запросы
автоматически не повторяются, чтобы не отправить сообщение дважды.

Одновременно выполняется один ответ Codex на всё приложение. Нет файловых
вложений, голосовых сообщений, синхронизации между устройствами, сложной памяти,
полного Markdown-рендерера и системы учётных записей веб-клиента. Для ответа
требуются интернет, доступная модель и лимиты существующей учётной записи Codex.
План Ubuntu 24.04 / Node.js 22 / 1 vCPU / 2 ГБ RAM — в `deploy/README.md`.

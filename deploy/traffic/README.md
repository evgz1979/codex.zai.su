# Независимый счётчик трафика VPS

Дата: 2026-11-06. Основа — vnStat 2.12 из официального Ubuntu-пакета
`vnstat_2.12-1_amd64.deb`. Счётчик работает отдельно от VPN и веб-приложения.

## Что измеряется

Измеряется общий трафик внешнего интерфейса **eth1**, через который идёт default
route VPS. Для сравнения с панелью хостера используется только **TX / исходящий**.
RX показывается отдельно, с TX не складывается. Счётчик не читает содержимое
сообщений, адреса сайтов, ключи VPN или трафик отдельных клиентов.

vnStat читает статистику интерфейса и сохраняет историю по часам, дням и месяцам;
он не перехватывает пакеты. Это описано в
[руководстве vnStat](https://manpages.ubuntu.com/manpages/noble/man1/vnstat.1.html).
Это независимая история на стороне гостевой ОС, а не точная копия методики
биллинга провайдера. Общий интерфейсный счётчик не определяет приложение,
которое создало расход.

История начинается **с момента установки**. Старый трафик не распределяется
задним числом. Показание панели, переданное пользователем, сохраняется отдельно
как наблюдение и не прибавляется к измерениям. Время обновления панели неизвестно.

GB — десятичные единицы: **1 GB = 1 000 000 000 байт**, MB = 1 000 000 байт.
Первый день и месяц неполные. Граница дня/месяца — Москва; TZ задаётся только
процессу счётчика, глобальное время сервера и VPN не меняется. Если период
биллинга провайдера другой, сравнивать следует прирост за одинаковое окно.

## Как посмотреть

На MacBook из папки проекта:

```bash
bash deploy/traffic/report.sh
```

Скрипт использует существующий SSH-алиас `lightnode-bkk`. Другой SSH target:

```bash
VPS_SSH=root@38.60.254.194 bash deploy/traffic/report.sh
```

На VPS:

```bash
python3 /opt/codex-zai-traffic/report.py
```

Доступны исходящие/входящие байты с начала истории, последние часы/дни/месяцы,
время последнего сохранения. Вывод приватный, через SSH; HTTP API и публичной
страницы статистики нет. Чтение раз в 5 секунд, запись БД раз в минуту, поэтому
отчёт может отставать примерно на минуту.

## Как прикинуть расход и проверить хостера

1. Записать TX из нашего отчёта и текущее показание панели хостера вместе со временем.
2. Поработать типичный час. Снова записать оба показания после обновления панели.
3. Вычесть начальные значения из конечных отдельно для каждого счётчика.
4. Оценка рабочего месяца: `GB за час × часов в день × рабочих дней`.
   Например, **если** час дал 0,25 GB, сценарий 8 часов × 22 дня — 44 GB.
   Это сценарий, а не прогноз и не стоимость услуги.
5. Для сверки с провайдером полезнее несколько суточных интервалов; учитывать
   округление панели, её задержку, границы периода, GB/GiB и методику учёта.

Два общих накопительных итога с разным началом нельзя напрямую сравнивать.
Установки, обновления и сетевые команды инструментов тоже могут создавать трафик.
Один рабочий час не доказывает расход всего месяца и не объясняет прошлый трафик.

## Изоляция и хранение

- `/opt/codex-zai-traffic/bin/vnstat` и `vnstatd` — отдельные бинарники.
- `/opt/codex-zai-traffic/report.py` — только чтение и форматирование.
- `/etc/codex-zai-traffic/vnstat.conf` — настройки счётчика.
- `/var/lib/codex-zai-traffic/` — SQLite и приватная начальная отметка, режим 0700.
- `codex-zai-traffic.service` — отдельный пользователь, пустые capabilities,
  NoNewPrivileges, лимит памяти 64 МБ и низкий CPUWeight.
- Новых слушающих портов нет. Настройки Xray/x-ui, firewall, маршруты и sysctl
  не меняются. `PrivateNetwork` не включать: он изолировал бы нужные счётчики сети.
- Только eth1; при изменении внешнего интерфейса требуется отдельная проверка.
- История: 5-минутная — 72 часа, почасовая — 60 дней, дневная — 366 дней,
  месячная — 24 месяца. Новые интерфейсы автоматически не добавляются.
- БД, отметки панели и журнал не коммитить. Существующая HTTPS-страница и приложение
  не получают доступа к этой статистике.

## Первичная установка

Сначала получить свежий снимок VPN через `deploy/https-test/vpn_snapshot.py`.
Проверить default route eth1, отсутствие старого счётчика и конфликтующих путей.
Запускать повторную первичную установку поверх существующей БД нельзя.

На VPS в отдельной временной папке:

```bash
apt-get download vnstat=2.12-1
```

`apt-get download` только получает файл; `apt install`, `dpkg -i`, обновления и
maintainer scripts не используются. Бинарники извлекаются через `dpkg-deb --extract`.
SHA-256 пакета закреплён в `prepare.sh`; libsqlite3 уже должна быть установлена.
Передать в папку `prepare.sh`, `vnstat.conf`, `codex-zai-traffic.service`,
`report.py` и исходный приватный снимок как `vpn-baseline.json`. Выполнить:

```bash
bash prepare.sh
# Если есть свежее показание панели: числовое GB и время его записи UTC
bash prepare.sh "$PROVIDER_GB" "$RECORDED_AT_ISO8601"
```

Эти строки — альтернативные варианты первичной установки. Не выполнять их
последовательно. Приватная отметка панели передаётся при конкретном запуске,
в исходниках/репозитории реальная статистика не хранится.

Переменные в примере нужно заполнить своими значениями заранее. После запуска
проверить отсутствие старого трафика в новой истории, появление интервалов и сравнить
снимки VPN до/после. Сервис сохраняет БД при корректной остановке. При сбое или
перезагрузке возможен неполный учёт последнего интервала; БД не восстанавливает
трафик, прошедший во время недоступности счётчика.

Первичная установка включает отдельный 8-секундный запуск с `vnstatd --sync`,
после которого проверяется, что старые интерфейсные итоги не попали в новую
историю. Обычные последующие запуски идут без `--sync`. Сами счётчики ядра,
сетевой интерфейс и VPN при этом не сбрасываются.

## Проверки и остановка

Проверено на VPS 2026-11-06: 6 тестов отчёта/единиц/начальной синхронизации,
реальная контрольная передача 64 КиБ, сохранение БД при рестарте только vnStat,
отсутствие новых TCP-слушателей, совпадение снимков VPN/firewall до и после.
После установки HTTPS-тест продолжает возвращать 200. Глобальное время сервера,
VPN и системные накопительные счётчики не сбрасывались. Приватные результаты
проверок и начальные отметки не включены в репозиторий.

```bash
python3 -m unittest discover -s deploy/traffic -p 'test_*.py' -v
bash -n deploy/traffic/prepare.sh deploy/traffic/report.sh
```

Остановить только учёт, сохранив БД:

```bash
sudo systemctl disable --now codex-zai-traffic.service
```

VPN, HTTPS и SSH продолжат работать. Для возобновления:

```bash
sudo systemctl enable --now codex-zai-traffic.service
```

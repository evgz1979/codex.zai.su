# Z AI Messenger

Локальный личный мессенджер для будущего `msg.zai.su`: одна лента, один список
диалогов и одно поле ввода. Сейчас подключается только личный Telegram через
teleproto. Сообщения разных адаптеров объединяются по времени; источник виден
маленькой подписью. Перед отправкой всегда выбран конкретный адресат.

Модуль независим от существующих `frontend/`, `backend/`, `shared/` Codex-клиента.
Они остаются на своих местах: перенос в `codex/` не требуется. Реальный checkout
на этом MacBook — `/Users/evgz/Documents/zai.su`, remote —
`https://github.com/evgz1979/codex.zai.su`.

## Запуск на MacBook

Нужен Node.js 22.16+ (ветка 22). Скрипт использует установленный в проекте
`.tools/node`, если он есть. Docker, отдельная СУБД и фоновые сервисы не нужны.

Из корня репозитория:

```bash
cd /Users/evgz/Documents/zai.su
bash messenger/scripts/npm.sh ci
bash messenger/scripts/npm.sh run build
bash messenger/scripts/npm.sh run setup
bash messenger/scripts/npm.sh run telegram:login
bash messenger/scripts/npm.sh start
```

Открыть **http://127.0.0.1:4318**. Войти с паролем, созданным командой `setup`,
и нажать «Обновить». Пароль задаётся минимум из 12 символов. Все поля в CLI
вводятся скрыто, без звёздочек и отражения текста. Не передавайте секреты
аргументами команд, через чат или переменные браузера.

Остановка — `Ctrl+C` в терминале сервера либо:

```bash
bash messenger/scripts/stop.sh
```

`npm run dev` перезапускает TypeScript-сервер при изменениях; интерфейс нужно
пересобирать отдельной командой `build`. Production-сервер раздаёт собранные
React-файлы и API с одного loopback-адреса, без CORS и второго HTTP-порта.

## Однократное подключение Telegram

1. В обычном браузере самостоятельно открыть [my.telegram.org](https://my.telegram.org).
   Войти своим номером телефона. Код приходит способом, выбранным Telegram.
2. Открыть **API development tools**, создать приложение: например, App title
   `Z AI Messenger`, Short name `zai_messenger`, Platform `Other`, описание
   `Personal local messenger`. Если форма требует URL — `https://msg.zai.su`.
   Развёртывать домен для локальной авторизации не нужно.
3. Получить свои `api_id` и `api_hash`. Не присылать их в чат, не делать коммит,
   не копировать в код, `.env`, браузерное приложение или логи.
4. Остановить Messenger. Выполнить `bash messenger/scripts/npm.sh run telegram:login`
   в собственном локальном терминале. Ввести `api_id`, `api_hash`, телефон с кодом
   страны, код входа и пароль Telegram 2FA, если он запрошен. При необходимости
   Telegram может запросить email и код его подтверждения.
5. Команда сохраняет зашифрованную сессию, не печатает её и не отправляет ни одного
   сообщения. Перезапустить Messenger, войти, нажать «Обновить».
6. Для ручной проверки выбрать «Избранное», отправить себе короткую тестовую строку,
   проверить её в официальном Telegram, затем проверить личный диалог и группу.
   Это выполняется владельцем аккаунта; автоматические тесты работают без него.

После перезапуска повторный код не нужен. Если Telegram отозвал сессию, повторить
`telegram:login`. Отзыв доступа: официальный Telegram → Настройки → Устройства →
найти **Z AI Messenger** → Завершить сеанс. Для смены аккаунта остановить сервер
и повторить авторизацию: старый кеш очищается после успешного входа.
Ошибки авторизации показываются без исходного исключения, чтобы исключить утечку.

Официальные инструкции: [получение API ID](https://core.telegram.org/api/obtaining_api_id),
[авторизация teleproto](https://docs.teleproto.dev/authentication),
[документация teleproto](https://docs.teleproto.dev/).

## Возможности и границы MVP

- Личные чаты и группы, единая хронологическая лента, поиск адресата.
- Одна и та же лента остаётся на экране при выборе адресата. Выбор добавляет
  последние сообщения этого диалога в общий поток и задаёт маршрут поля ввода.
- Источник указан около сообщения и рядом с получателем. Сервер сверяет
  `sourceId + conversationId + recipientId`; несовпадение отклоняется.
- Черновик хранится в памяти браузера отдельно для каждого диалога, очищается
  после отправки и выхода. Текст отправляется буквально, без Markdown и link preview.
- Кнопка ручного обновления, счётчики непрочитанных в загруженных диалогах.
  Общая лента не помечает всё прочитанным автоматически: есть явная кнопка
  «Отметить прочитанным» у выбранного адресата.
- Максимум 100 записей Telegram dialogs, из них личные чаты и группы. Для общей
  ленты — по 20 последних сообщений 12 наиболее свежих разговоров. При выборе
  диалога — до 40. Не более 400 сообщений в кеше. Пагинации всей истории нет.
- Нет фото, файлов, звонков, push, секретных чатов, broadcast-каналов. Вложения
  обозначаются текстом, без загрузки медиа. Форумы с темами и платные сообщения
  пока доступны только для чтения, чтобы не выбирать тему и не тратить Stars неявно.
- Интерфейс адаптирован к iPhone: выдвижной список, safe-area, поле ввода 16px,
  `dvh`, большие кнопки и сохранение доступности отправки при уменьшении высоты.

## Архитектура

```text
messenger/
  frontend/                  # единый React + TypeScript интерфейс
  backend/
    core/source-adapter.ts   # общий контракт SourceAdapter
    core/service.ts          # сборка ленты, лимиты, проверка маршрута, дедупликация
    connectors/telegram/     # единственная рабочая реализация: TelegramAdapter
    auth/                    # пароль, скрытый CLI-ввод, веб-сессии, CSRF
    storage/                 # SQLite и отдельное зашифрованное хранилище сессии
    http.ts                  # фиксированный небольшой HTTP API
  shared/types.ts            # Source, Conversation, Message, Recipient,
                             # Attachment, DeliveryStatus, Destination
  test/                      # синтетические тестовые адаптеры, не production
```

Будущие `WhatsAppAdapter`, `CodexAdapter`, `EmailAdapter` должны реализовать
`SourceAdapter` и регистрироваться в `backend/index.ts`. Сейчас таких классов,
экранов и имитаций подключения нет. Названия провайдеров не определяют структуру UI.
Идентификаторы включают источник, тип сущности и экранированный native ID.
Telegram message ID дополнительно включает диалог: даже совпадения внутри групп
не приводят к коллизиям. Для будущего объединения контактов маршруты остаются
раздельными и явными. Отправка из общей ленты без выбранного адресата запрещена.

Ни одного импорта существующего Codex-клиента, App Server, SDK ИИ или API ИИ в
модуле нет. Telegram-тексты идут только между браузером, локальным сервером,
локальным SQLite и Telegram. Добавление будущего ИИ-коннектора само по себе
не разрешает передавать в него сообщения других источников.

## Хранение и защита

`messenger/.local/` игнорируется Git существующим правилом `.local/`:

- `messenger.sqlite`: scrypt-хеш пароля и минимальный кеш (кеш не шифруется).
- `telegram.enc`: `api_id`, `api_hash`, StringSession, AES-256-GCM.
- `vault.key`: случайный локальный ключ шифрования.
- `server.pid`: PID только этого локального сервера.

Каталог имеет права `0700`, файлы `0600`. Ключ рядом с шифротекстом защищает
от случайного чтения/копирования отдельного файла, но не от доступа к macOS-аккаунту.
Для защиты самого MacBook используйте FileVault. Не копируйте `.local/` в Git,
публичные бэкапы или диагностические отчёты. Логи не содержат входных данных,
переписок, сессий и исходных исключений Telegram. Browser bundle не включает teleproto.

Кеш старше суток удаляется при запуске. Очистить его вручную (при остановленном сервере):

```bash
bash messenger/scripts/npm.sh run cache:clear
```

Веб-сессия живёт до 8 часов, только в памяти сервера; cookie `HttpOnly`,
`SameSite=Strict`. POST требует точного Origin и CSRF-токена; Host проверяется
против loopback-адреса. Вход ограничен 5 попытками в минуту, запросы ограничены
по размеру, CSP запрещает внешние скрипты/соединения. Пароль и сессия Telegram
никогда не возвращаются API. Тело сообщения не вставляется как HTML.
Неизвестный результат отправки не вызывает автоматический повтор UI. Повтор
того же request ID в течение 15 минут возвращает прежний результат в рамках
одного процесса. После рестарта долговременной дедупликации нет: сначала
обновите ленту. teleproto сохраняет один random ID при внутренних RPC-повторах.

## Проверки

```bash
bash messenger/scripts/npm.sh test
bash messenger/scripts/npm.sh run build
bash messenger/scripts/npm.sh exec -- playwright install chromium webkit
bash messenger/scripts/npm.sh run test:browser
```

Core/HTTP-тесты проверяют межисточниковые коллизии, общую ленту, маршрут отправки,
дедупликацию, границы кеша, права файлов, шифрование, scrypt, отзыв сессий, rate limit,
Host, Origin, CSRF и отсутствие исходных исключений в API. Браузерные сценарии:
Chromium desktop, WebKit iPhone 13 и iPhone SE, вход/выход, общая лента из двух
синтетических источников, смена адресата и черновика, отправка, непрочитанные,
обновление, отсутствие горизонтального скролла и доступность composer при малой высоте.
Тестовые серверы используют только `127.0.0.1:14318` и `127.0.0.1:14319`, временные
БД и фиктивные пароли. Скриншоты — в игнорируемом `messenger/test-results/`.
Реальный iPhone/Safari и реальная Telegram-сессия требуют отдельной ручной проверки.

## Перед будущим публичным запуском

Публичного запуска сейчас нет: сервер жёстко слушает `127.0.0.1:4318`, домен
`msg.zai.su` не настраивается. Предусмотрен обязательный парольный вход.
Для будущего HTTPS-входа потребуется отдельное подтверждённое задание: доверенный
reverse proxy, точный публичный Origin/Host, cookie `Secure`, проверка login/CSRF
через HTTPS и защиты от перебора. Текущий HTTP-cookie предназначен только для
loopback. Сервер не принимает настройки публичного bind из переменных окружения.
VPS, Caddy, Xray/VPN, DNS и работающий HTTPS этим модулем не изменяются.

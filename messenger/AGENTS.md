# Z AI Messenger

- По заданию от 2026-11-08 разрешены закрытые личные аккаунты семьи и друзей.
  Пользователей добавляет только владелец в своей админке. Интерфейс и документация на русском.
- В интерфейсе только функциональные и технические тексты: названия действий,
  поля, статусы, ошибки и необходимые инструкции. Никаких слоганов, рекламных
  блоков, приветственных речей и описаний «пространства» или пользы продукта.
- Единая лента и одно поле ввода; не добавлять вкладки и экраны по провайдерам.
- Источники подключаются через `SourceAdapter`: Telegram и серверный браузерный
  WhatsApp. Привязка WhatsApp — через QR в личной админке. Будущие источники не имитировать.
- Перед отправкой проверять источник, диалог и получателя. Черновики разных
  получателей изолировать. Не передавать сообщения Telegram в ИИ.
- Существующий Codex-клиент вне этого модуля не изменять.
- Секреты, сессии, БД, кеш, логи и скриншоты тестов не коммитить.
- Backend только на `127.0.0.1`. Развёртывание Messenger разрешено заданием
  от 2026-11-07 через deploy/messenger/deploy.sh на msg.zai.su:8443.
  VPN/Xray/x-ui, 443, firewall/sysctl и Codex-site не менять; до/после сравнивать VPN snapshot.
- Настройки источников только в личной /admin; разные роли/cookie/API admin и chat.
  Новые ссылки гостей /username/, созданные раньше /u/username/ сохраняются.
  На главной имя и только поле пароля; в личной админке краткая инструкция получения Telegram API.
  БД, Telegram, медиакеш, cookie и worker каждого аккаунта изолированы.
  Панель владельца управляет именами и блокировками, не предоставляет чужие переписки.
  Невыбранные диалоги не читать, не отправлять и не отдавать через API.
  После исключения архив не удалять. Секреты production только вне каталога кода.
- По заданию от 2026-11-08 новые личные входящие от людей автоматически разрешаются
  до чтения и появляются в общем списке. Старые невыбранные и явно исключённые
  диалоги не подключать повторно; боты, группы и каналы автоматически не добавляются.
- Для браузерного WhatsApp по уточнению владельца новые чаты тоже подключаются
  только вручную галочками в личной админке; автоматическая политика Telegram сохраняется.
- На этапе тестирования WhatsApp доступен только владельцу. Остальным показывать
  серый неактивный раздел с инструкциями, без WhatsApp-запросов и адаптера;
  серверные WhatsApp API личных пользователей возвращают 403.
- Реально видимые сообщения активной ленты автоматически отмечаются прочитанными
  через источник. Открытие приложения само по себе не сбрасывает скрытые сообщения.
- По заданию от 2026-11-08 при обычном входе показывать список чатов; при возврате
  сохранять открытый экран. Клик push выбирает разрешённый диалог после входа.
  Ручной выбор отменяет поздний автопереход;
  активную переписку, черновик и просмотр вложения автоматическим обновлением не менять.
- Проверки из корня: `bash messenger/scripts/npm.sh test`,
  `bash messenger/scripts/npm.sh run build`,
  `bash messenger/scripts/npm.sh run test:browser`.
- Документация: [оглавление](docs/README.md), порядок поддержки —
  [docs/development.md](docs/development.md). README оставлять кратким;
  контракты, сценарии и историю хранить в соответствующих разделах docs.
- Перед именованным определением TS/MJS поддерживать две строки `//:`:
  назначение и существенный контракт. Справочник генерируется из AST;
  его страницы вручную не редактировать, построчные ссылки не добавлять.
- При изменении кода или документации выполнить docs:build, docs:check и docs:test
  через `bash messenger/scripts/npm.sh run ...`. Не читать рабочую БД ради
  справочника; не объявлять прежнюю проверку Telegram/iPhone новой live-проверкой.
- Коммиты разделять по темам. Уже отправленную историю не переписывать.

# Уведомления на iPhone

## Включение

Для личного аккаунта открывайте выданную владельцем ссылку: `/username/` для
новых пользователей или сохранённую `/u/username/` для прежних. Существующую
установку по старой ссылке менять не требуется; её manifest и scope сохраняются.

1. Откройте [Messenger](https://msg.zai.su:8443/) в Safari на iPhone с iOS 16.4 или новее.
2. В меню «Поделиться» выберите «На экран Домой» и добавьте приложение.
3. Запустите Messenger с новой иконки и войдите паролем чата.
4. Откройте список диалогов → «Уведомления» → «Включить» и разрешите системный запрос.
5. Нажмите «Проверить». Затем закройте приложение и проверьте новое входящее
   из выбранного в /admin диалога.

Доставка работает при закрытом приложении. Добавление на экран «Домой» и явное
разрешение требуются iOS; обычной вкладки Safari недостаточно. Условия —
в [документации WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
Звук, экран блокировки и фокусирование регулируются настройками iPhone.

В уведомлении только «Z AI Messenger — Новое сообщение». Имена, названия,
тексты и вложения в push не передаются. В зашифрованном payload есть только
общий conversationId для перехода, без native peer и реквизитов. Нажатие открывает
соответствующий разрешённый диалог; при истёкшей веб-сессии потребуется вход.
Service Worker не сохраняет переписку, страницы
или токены и не перехватывает HTTP-запросы.

При обычном запуске с иконки открывается список чатов. Возвращение из фона
сохраняет текущий экран, выбранную переписку, черновик и открытое вложение.
Нажатие push открывает его разрешённый диалог после входа; явный клик имеет
приоритет, черновики разных адресатов остаются раздельными.

Для существующего окна worker передаёт фиксированную команду через postMessage;
новое окно получает общий ID в fragment `/#conversation=…`. Fragment не передаётся
HTTP-серверу и очищается после разрешения маршрута. Клиент сначала получает свежий
allowlist и только затем вызывает open. Исключённый или неизвестный ID не уходит
в open API; вместо него выбирается свежий непрочитанный либо список чатов.
Старые уведомления без ID и проверочное уведомление используют тот же запасной
переход. Ручной выбор отменяет запоздалую автоматическую загрузку.

## Доставка и ограничения

Новые входящие выбранных диалогов поступают событиями источника или сверкой
свежей головы уже инициализированного кеша. Повторы ID, исходящие, правки,
начальная и старая история не вызывают уведомлений. Сообщения до включения
устройства и старше часа при восстановлении пропуска не доставляются.
Перед отправкой повторно проверяются выбор и существование сообщения.
Близкие события объединяются; badge берётся из непрочитанных выбранных диалогов.
После 600 мс просмотра в активной ленте сообщения отмечаются прочитанными через
Telegram. Подтверждается точный видимый messageId, скрытые сообщения не сбрасываются.
При нулевом счётчике значок очищается, доставленные уведомления закрываются.
При возврате в приложение значок уточняется; поздний push не устанавливает старое
число поверх открытого чата. Новые личные контакты автоматически разрешаются
по входящему и уведомляют с первой свежей головы; исключённые не возвращаются.
Подробности — [ADR-0008](adr/0008-visible-reads-and-new-contacts.md).
После позднего push Worker также уточняет число через защищённый GET badge,
даже если окно уже закрыто. Запрос не читает переписку; при истёкшей веб-сессии
или отсутствии связи используется исходный push-count. Проверочное уведомление
не закрывается автоматически из-за нулевого счётчика.

Иконки установки теперь квадратные с непрозрачным фоном до краёв, без собственного
скругления: его применяет iOS. Обновление интерфейса выполняется внутри приложения; переустановка для
обычных выпусков не нужна.

[web-push](https://github.com/web-push-libs/web-push) шифрует payload и подписывает
запрос VAPID. Сервер отправляет исходящий HTTPS к push-сервису Apple; новые
входящие порты и аккаунт Apple Developer не требуются. Окончательный показ
зависит от ОС и провайдера: принятие проверки провайдером не доказывает показ
на физическом iPhone.

Очередь ограничена 128 сообщениями в памяти и теряется при аварийной остановке.
TTL обычного push — пять минут, проверки — одна минута. Временный отказ сохраняет
подписку без бесконечного повтора; следующие новые события доставляются обычно.

## Хранение и отзыв

Пара VAPID создаётся один раз в `push.vapid`, подписки — в `push.devices`
приватной SQLite: endpoint, ключи устройства, время включения/истечения и
отпечаток версии пароля чата. Они не попадают в Git, релиз, URL и журналы.
API выдаёт только публичный VAPID-ключ и статус конкретного endpoint.
Истечение восьмичасовой веб-сессии и рестарт backend сохраняют доставку.

До десяти устройств, подписка на 90 дней после последнего включения.
После истечения включение нужно повторить. «Выключить» и явный «Выйти» отзывают
устройство, смена пароля чата — все подписки, в том числе при смене через CLI.
HTTP 404/410 от провайдера удаляет запись. Обновление кода сохраняет VAPID-пару.

## HTTP API

Роль `chat`, её cookie; POST также требует точный Origin и CSRF.

| Метод | Запрос | Ответ |
| --- | --- | --- |
| GET `/api/chat/push/config` | — | `{ publicKey }` |
| POST `/api/chat/push/status` | `{ endpoint }` | `{ enabled }` |
| POST `/api/chat/push/subscribe` | `{ subscription: { endpoint, keys: { p256dh, auth } } }` | `{ ok: true }` |
| POST `/api/chat/push/remove` | `{ endpoint }` | `{ ok: true }` |
| POST `/api/chat/push/test` | `{ endpoint }` | `{ ok: true }` после принятия провайдером |
| POST `/api/chat/logout` | `{ pushEndpoint? }` | `{ ok: true }`, endpoint отзывается |

Endpoint: только HTTPS на стандартном порту Apple, FCM или Mozilla; произвольные
хосты, credentials, query и fragment запрещены. P-256 и auth проверяются до записи.
Публичная статика установки: `/manifest.webmanifest`, `/sw.js`, `/icon-192.png`,
`/icon-512.png`, `/apple-touch-icon.png`; кеш отключён.

## Проверки

`test/push.test.ts` проверяет события, права, отзыв и постоянство подписок,
HTTP API, шифрование настоящей библиотекой и Service Worker. Транспорт тестовый;
Apple и Telegram не вызываются. `test/browser/notifications.spec.ts` проверяет
инструкцию iPhone и включение/проверку/отключение на подменённых браузерных API.
Настоящая доставка и физический iPhone проверяются владельцем отдельно.


## Обновление установленного приложения

Внизу списка чатов доступны номер версии и «Обновить приложение». При новой
сборке появляется уведомление и такая же кнопка в открытой переписке. Проверка
выполняется при запуске, возвращении, восстановлении сети и раз в минуту в
видимом окне. Открытая переписка сама не перезагружается.

Нажатие получает актуальную версию без HTTP-кеша, затем заново открывает тот же
адрес с новым параметром. При черновиках нужно подтвердить их потерю; отмена
сохраняет текст. Во время отправки или просмотра вложения обновление недоступно.
При отсутствии связи остаётся текущая страница с сообщением об ошибке. Manifest,
worker и подписки не удаляются. Истёкший вход может потребовать пароль обычным способом.

Чтобы впервые получить кнопку в уже открытой старой версии на iPhone, полностью
закройте Messenger в переключателе приложений и откройте с существующей иконки.
[Инструкция Apple по закрытию приложения](https://support.apple.com/en-us/109359).
После загрузки версии 0.12.3 следующие выпуски применяются этой кнопкой.
Физическая установленная PWA проверяется владельцем отдельно; WebKit-эмуляция
не воспроизводит все способы восстановления окна iOS.

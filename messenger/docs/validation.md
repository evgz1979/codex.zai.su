## Исходная проверка MVP · 7 ноября 2026

Основание: коммит реализации `eec41cf`. Результаты ниже относятся к созданию MVP,
а не к повторной live-проверке после оформления документации.

Среда: MacBook, Node.js 22.23.4, teleproto 1.232.1, встроенный `node:sqlite`.
SQLite в Node.js 22 выводит штатное предупреждение ExperimentalWarning.

Результаты:

- `bash messenger/scripts/npm.sh run build` — успешно; TypeScript frontend/backend,
  Vite production build. Клиентская сборка около 256 КБ без gzip; teleproto,
  `StringSession`, `apiHash` и `api_hash` в ней отсутствуют.
- `bash messenger/scripts/npm.sh test` — 9/9: ядро, HTTP-защита и Telegram DTO.
- `bash messenger/scripts/npm.sh run test:browser` — 3/3: Chromium desktop
  1440×1000, WebKit iPhone 13 390×664 и iPhone SE 320×568; дополнительно высота 420px.
  Проверены вход/выход, общая лента двух тестовых источников, явный адресат,
  изоляция черновиков, отправка в выбранный источник, обновление, непрочитанные,
  горизонтальные границы и доступность composer при уменьшении высоты.
- Скриншоты с синтетическими сообщениями осмотрены. На iPhone SE исправлено
  скрытие действия «Отметить прочитанным» в коротком viewport.
- Строгая CSP остаётся включённой при браузерных тестах. Только во время снимка
  игнорируется конкретное сообщение WebKit о блокировке служебного inline-стиля
  screenshotter Playwright; до снимка и после него ошибки консоли запрещены.
- `bash scripts/npm.sh test` — 4/4, `bash scripts/npm.sh run build` — успешно
  для существующего Codex-клиента. Его исходные файлы и package.json не менялись.
- Production entrypoint запущен на `127.0.0.1:4318`; вручную открыт экран первого
  запуска с обязательным созданием пароля, без тестовой авторизации в реальном хранилище.
- `git check-ignore` подтверждает исключение SQLite, зашифрованной сессии,
  ключа, node_modules и браузерных скриншотов. Runtime-данные не входят в коммит.

Границы проверки: реальный Telegram-аккаунт не авторизован, отправки в Telegram
не было. Физический iPhone и нативный Safari не проверялись: мобильная проверка
выполнена WebKit с эмуляцией устройств. Владельцу нужно выполнить локальную
авторизацию из [инструкции Telegram](telegram.md) и проверить «Избранное», личный диалог и группу.
VPS, VPN, Xray, Caddy, DNS и HTTPS не затрагивались. Публичного развёртывания нет.

# Запуск и эксплуатация

## Запуск на MacBook

Нужен Node.js 22.16+ (ветка 22). Скрипт использует установленный в проекте
`.tools/node`, если он есть. Docker, отдельная СУБД и фоновые сервисы не нужны.

Из корня репозитория:

```bash
cd /Users/evgz/Documents/zai.su
bash messenger/scripts/npm.sh ci
bash messenger/scripts/npm.sh run build
bash messenger/scripts/npm.sh run setup
bash messenger/scripts/npm.sh run telegram:login
bash messenger/scripts/npm.sh start
```

Открыть **http://127.0.0.1:4318**. Войти с паролем, созданным командой `setup`,
и нажать «Обновить». Пароль задаётся минимум из 12 символов. Все поля в CLI
вводятся скрыто, без звёздочек и отражения текста. Не передавайте секреты
аргументами команд, через чат или переменные браузера.

Остановка — `Ctrl+C` в терминале сервера либо:

```bash
bash messenger/scripts/stop.sh
```

`npm run dev` перезапускает TypeScript-сервер при изменениях; интерфейс нужно
пересобирать отдельной командой `build`. Production-сервер раздаёт собранные
React-файлы и API с одного loopback-адреса, без CORS и второго HTTP-порта.

## Повторный запуск и изменения

После первого setup и авторизации достаточно `bash messenger/scripts/npm.sh start`.
После изменения frontend/backend выполнить build и перезапустить сервер.
`npm run dev` отслеживает только TypeScript backend; горячая перезагрузка React
для этого скрипта не настроена. Не запускать второй экземпляр на том же порту.

Очистка кеша при остановленном сервере:

```bash
bash messenger/scripts/npm.sh run cache:clear
```

Очистка сохраняет пароль и Telegram-сессию. Смена пароля — команда setup и
перезапуск сервера; смена аккаунта — [telegram:login](telegram.md) и перезапуск.

## Launcher и области команд

Корневой launcher.json сейчас содержит только Codex-клиент. Messenger в него
не добавлен и запускается приведёнными командами. Исходники Launcher не меняются.
Команды `bash scripts/npm.sh ...` без префикса messenger относятся к Codex-клиенту;
у модулей отдельные package.json, node_modules, dist и runtime-данные.

## Диагностика

| Состояние | Действие |
| --- | --- |
| Нет Node/npm | Установить Node.js 22.16+ ветки 22 либо использовать локальный .tools/node |
| Вместо интерфейса 404 | Выполнить build модуля; сервер раздаёт dist/client |
| 403 при обращении | Открыть точный адрес 127.0.0.1:4318; localhost и другие Host не принимаются |
| «Аккаунт не подключён» / ошибка обновления | Проверить доступ к Telegram; при отсутствии сессии остановить сервер и выполнить telegram:login |
| 401 | Повторить веб-вход: сессии не переживают рестарт и истекают через 8 часов |
| 429 | Подождать минуту перед следующим вводом пароля |
| Неизвестен результат отправки | Вручную обновить ленту и сверить Telegram перед новой отправкой |
| Порт 4318 занят | Остановить подтверждённый экземпляр Messenger штатным stop.sh; чужие процессы не завершать |
| stop.sh не находит процесс | Для dev использовать Ctrl+C в его терминале; stop.sh проверяет команду собранного entrypoint |

Ключи, cookie, сессию и текст переписки в диагностику не вставлять. Общие ошибки
Telegram намеренно не показывают исходное исключение. Сетевые настройки VPN,
VPS, Caddy и HTTPS для диагностики локального модуля не меняются.

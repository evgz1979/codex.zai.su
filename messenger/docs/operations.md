# Эксплуатация

## Рабочие адреса

- Чат: **https://msg.zai.su:8443/**.
- Админка: **https://msg.zai.su:8443/admin**.
- Backend: `127.0.0.1:4318`, доступен только внутри VPS.

Пользовательское тестирование выполняется на LightNode после автоматических
проверок на MacBook. Роли admin и chat имеют разные пароли. В чате нет настроек
источников; подключение Telegram и выбор диалогов выполняются в админке.

## Первоначальный доступ

Скрипт развёртывания один раз генерирует два случайных пароля по 32 символа.
На MacBook они находятся в `~/Library/Application Support/Z AI Messenger/deploy/initial-credentials.txt`
с правами 0600, вне Git. Файл открывает только владелец; его содержимое не нужно
передавать в чат. На VPS передаются Argon2id-хеши, а не исходные пароли.
Повторный deploy не перезаписывает настроенные пароли.

После входа в /admin можно изменить пароли в разделе «Доступ». Новый пароль
содержит 8–512 символов. Смена отзывает все сессии соответствующей роли.
Пароль Telegram 2FA — другой секрет;
он не используется для входа в Messenger.

## Текущий доступ и папки

Работа с закладками описана в [руководстве Telegram](telegram.md). После
обновления приложения повторяется веб-вход нужной ролью; сохранённая сессия
Telegram и выбранные в SQLite диалоги остаются. Нажатие «Получить список диалогов»
обновляет также названия, порядок и состав папок. Изменения галочек во всех
закладках сохраняются общей кнопкой «Сохранить выбор».

В чате ничего обновлять вручную не нужно. Новые сообщения приходят автоматически,
старые открываются при прокрутке вверх из SQLite. Это работает и в общей ленте,
и у отдельного адресата. Полная история отмеченных диалогов собирается на сервере
в фоне, даже при закрытом браузере; текущий прогресс обозначен над лентой.
Первичная загрузка большого архива занимает время. Уже записанные сообщения
открываются без ожидания Telegram. Повторно подключать аккаунт после обновления не нужно.

Если изменён пароль через раздел «Доступ», старое значение из первоначального
локального файла больше не подходит. Разные роли имеют разные пароли, а облачный
пароль Telegram используется только при авторизации источника.

## Развёртывание после изменения кода

Из корня checkout `/Users/evgz/Documents/zai.su`:

```bash
bash messenger/scripts/npm.sh run docs:build
# Сохранить изменения тематическими коммитами.
bash deploy/messenger/deploy.sh
```

Deploy требует чистую рабочую копию, выполняет сборку, server/browser/docs и
Caddy guard тесты, push, упаковку, SSH-установку и внешнюю HTTPS-проверку.
Нет отдельного пользовательского локального этапа. Детали и откат —
[deployment.md](deployment.md) и [скрипты](../../deploy/messenger/README.md).

## Диагностика на VPS

```bash
systemctl status zai-messenger.service --no-pager
systemctl show zai-messenger.service -p MemoryCurrent -p User -p ActiveState
curl -f -H 'Host: msg.zai.su:8443' http://127.0.0.1:4318/healthz
journalctl -u zai-messenger.service --no-pager -n 30
```

В журнал не включаются тела запросов, исходные исключения Telegram, коды,
пароли или сообщения. Ошибка 401 требует входа нужной ролью; 403 — проверки
выбора диалога, Origin/CSRF; 429 — ожидания минуты. При неизвестной отправке
дождаться автоматической сверки и проверить Telegram до повтора.

Ограничение Telegram при подключении источника показывается под статусом
авторизации и может длиться дольше минуты. Это отдельное ограничение от HTTP 429
веб-входа. Значение unknown не доказывает ошибку API-ключей. Для диагностики
достаточен безопасный текст причины; телефон, api_hash, коды и 2FA не прикладываются.

`setup` остаётся локальной аварийной командой задания двух паролей со скрытым
TTY-вводом. В production ей нужен `MESSENGER_DATA_DIR=/var/lib/zai-messenger`.
Обычная эксплуатация выполняется через админку. Старой CLI-команды
telegram:login больше нет. Корневые scripts/npm.sh и launcher.json относятся
к существующему Codex-клиенту, их runtime не изменён.

## Вложения

В ленте показываются миниатюры фото, видео и документов, если Telegram их предоставляет.
Нажатие открывает фото, видео или аудио в окне. PDF открывается отдельной вкладкой
по кнопке «Открыть PDF», текстовый файл отображается в окне просмотра. «Открыть
отдельно» открывает поддерживаемый формат в браузере; «Поделиться…» доступно при
поддержке передачи файлов системным меню. Скачивание в «Загрузки» происходит только
по отдельному действию «Скачать». Браузер не может напрямую запустить macOS Preview.app.

Сервер автоматически скачивает оригиналы и миниатюры выбранных чатов за последние
5 дней, затем все новые вложения, даже при закрытом браузере. Первичное заполнение
идёт постепенно в фоне. Текстовый кеш по-прежнему содержит всю историю. Старые
вложения загружаются при открытии, старые превью — при появлении в ленте.
Повторное открытие готового кеша не обращается к Telegram. Дисковый LRU-бюджет —
512 МиБ / 2048 записей; после вытеснения файл снова загружается по запросу.

Лимит оригинала — 32 МиБ, миниатюры — 512 КиБ. Более крупные оригиналы открываются
в официальном Telegram. Кодеки зависят от Safari/браузера: если воспроизведение
недоступно, используйте системное меню или сохранение. Закрытие отменяет незавершённую
интерактивную загрузку; отзыв доступа закрывает просмотр. Повторно подключать Telegram
после обновления не нужно. Отправка файлов этим этапом не добавлена.

# Данные

WhatsApp хранит браузерный профиль отдельно: `/var/lib/zai-whatsapp/<server-key>/`.
Backend хранит `whatsapp.enabled` и общий выбранный кеш, без cookie WhatsApp.
Отметка `linked` разрешает восстановление ранее готовой сессии. Временный QR
существует в памяти worker и личной admin-страницы, без offline-хранилища.

## Чтение без сети на устройстве

После успешного входа приложение сохраняет в IndexedDB список до 200 свежих
чатов, последние загруженные тексты и расшифровки: до 100 сообщений одного чата,
до 1000 всего и не более 4 МиБ JSON. В видимом приложении автоматически сохраняются
последние пять сообщений каждого выбранного чата, даже если его не открывали.
Одна последовательная очередь запрашивает пакеты по 20 чатов, обновляется раз
в 30 секунд и при возвращении из фона. Она читает только SQLite сервера и не
вызывает Telegram/open/read, не меняет текущий экран или границы просмотра.
Статус «Сохраняются чаты: X/Y» отображается до подготовки всех доступных голов.
Вложения не сохраняются; небольшие
фото из метаданных списка остаются доступны. Черновики остаются в памяти окна.

При открытии чата или общей ленты приложение читает сохранённую первую страницу
из IndexedDB независимо от состояния связи. При наличии сети свежая страница
с сервера обновляет уже открытую ленту в фоне.

Ключ записи — личный API-префикс: владелец и гости изолированы; короткая и прежняя
ссылка одного гостя используют один ключ. В кеше только публичное имя аккаунта,
срок подтверждённого входа, снимок и сообщения. Пароли, cookie, CSRF и Telegram-сессии
не записываются. Без сети доступны список, ранее загруженные чаты и прокрутка
сохранённой части; отправка, отметки прочтения и новая расшифровка отключены.
При возвращении связи сначала проверяется веб-вход и восстанавливается CSRF,
затем текущий экран обновляется без автоматического переключения адресата.

Чтение действует до истечения веб-сессии (максимум 8 часов). Выход очищает кеш;
локальный выход без сети сохраняет только флаг для последующего отзыва cookie
на сервере. Авторизация другого аккаунта того же адреса заменяет прежний кеш.
Снятие выбора, удаления, reset и отказ входа очищают локальные данные при связи.
Ошибка квоты или запрет IndexedDB сохраняют обычную работу приложения по сети.
Опрос прежней ревизии не перезаписывает кеш и не меняет время сохранения.
Повторная фоновая порция с теми же сообщениями также не создаёт лишней записи.
В лимите сообщений сначала резервируются по пять записей каждого чата;
остальные места занимают просмотренные страницы. При нехватке байтов сначала
удаляются старые записи, сохраняя хотя бы последнее сообщение каждого чата,
затем небольшие фото. Старый ответ не откатывает правку или готовую расшифровку.

Service Worker отдельно сохраняет HTML личного чата и JS/CSS той же сборки,
чтобы приложение открывалось после закрытия без интернета. Админка, API,
version.json, токены и переписка не кешируются worker. Первый автономный запуск
возможен после одного успешного открытия с сетью. Кеш браузер может удалить
при очистке данных сайта или нехватке места.

## Расположение

Production: `/var/lib/zai-messenger`, отдельный от кода `/opt/zai-messenger/releases`.
Путь задаётся MESSENGER_DATA_DIR; отсутствие внешнего абсолютного пути блокирует
production. Обновление/откат кода не копирует и не заменяет этот каталог.

Владелец сохраняет файлы в корне. Личные пользователи хранят такой же независимый
набор в `users/<UUID>/`; UUID создаётся сервером и не зависит от имени ссылки.
В `settings.accounts.v1` владельца находится только реестр имён, UUID, блокировок
и необязательных публичных путей `path`. Старые записи без `path` сохраняют
`/u/username/`; новые получают `/username/`. Чтение реестра не переписывает данные.
Хеши, ключи и переписка гостей в реестр не копируются. Блокировка сохраняет данные.

| Файл | Данные |
| --- | --- |
| messenger.sqlite | Настройки, хеши ролей, выбор диалогов, полный текстовый кеш |
| telegram.enc | AES-256-GCM: apiId, apiHash, StringSession, accountId |
| vault.key | Локальный ключ шифрования |
| attachments/ | Приватный дисковый кеш оригиналов и миниатюр, имена SHA-256 |
| server.pid | PID обычного backend |

[DDL из исходников](reference/sqlite-schema.md) строится без чтения рабочей БД.

| Таблица | Назначение |
| --- | --- |
| settings | `auth.admin`, `auth.chat`, время последнего снимка |
| selected_conversations | Разрешённые вручную и автоматически новые личные контакты |
| conversation_policy | Исходные и явные исключения по источнику; переживают рестарт |
| conversation_cache | DTO ранее синхронизированных диалогов |
| message_cache | Message DTO с conversation_id, датой и source_key |
| message_tombstones | Ключи подтверждённых удалений против запоздалой страницы |
| media_preload | Версия сообщения, вариант медиа и результат/время повтора фоновой загрузки |
| sync_state | Курсоры истории, свежей сверки и контрольная страница каждого диалога |

Запросы параметризованы. Выбор меняется атомарно. Кеш сообщений больше не
усекается до 40: сохраняется вся доступная текстовая история выбранных диалогов.
Индекс conversation_id/date/id обслуживает страницы по 10 без чтения всего архива.
Общая страница объединяет не более 11 кандидатов на каждый выбранный диалог.
Исключение сохраняет архив, прекращая его синхронизацию и доступ через API.
cache:clear явно удаляет кеш и прогресс, сохраняя пароли, выбор и Telegram-сессию;
фон затем заполняет выбранную историю заново.

Миграция добавляет source_key, индексы и sync_state без удаления прежних записей.
Сообщения записываются транзакцией до сохранения курсора. Контрольные ID последней
страницы позволяют восстановить историю после отката на старую версию с усечением.
Курсор браузера содержит только дату и общие ID; он не является MTProto-ключом.

## Идентификаторы и DTO

Модели: [shared/types.ts](../shared/types.ts). Message содержит id, sourceId,
conversationId, sender, date, text, outgoing, status, attachments и sourceKey. editedAt сохраняет время известной правки; поздняя старая страница
не отменяет более свежую правку или известное удаление.
sourceKey — логический идентификатор сообщения источника, не секрет. Для Telegram
личные/обычные групповые удаления имеют общую область ID, каналы — собственную. Conversation
имеет kind direct/group/channel, recipient, unreadCount и canSend. Destination
фиксирует sourceId + conversationId + recipientId и проверяется сервером.

ID строится из экранированных компонентов источника, типа и native ID. После
веб-авторизации Telegram sourceId имеет вид `telegram-<accountId>`. Message ID
дополнительно включает диалог. Аккаунты, источники и типы сущностей не пересекаются.
Текущий TelegramAdapter устанавливает только received/sent; типы delivered/read
в общем контракте не означают подтверждение чтения Telegram.

ConversationFolder содержит id, sourceId, title и conversationIds. ID папки
включает тип folder, например `telegram-<accountId>:folder:<nativeId>`. Список
содержит только ID текущего каталога; повторения между папками разрешены.
ConversationCatalog дополняет диалоги папками и признаком truncated, а admin DTO
добавляет selectedIds. Папки не записываются в отдельную таблицу разрешений.

## Память

Сервер: административные сессии и CSRF, rate limit, временный процесс Telegram-входа,
безопасная категория отказа, каталог метаданных, Promise refresh/send. После
обработки папок адаптер сохраняет только ID и native peer диалогов; их последние
сообщения из ответа GetDialogs не становятся кешем невыбранной истории.

Клиент: снимок, адресат, раздельные черновики и состояние форм; в админке —
полученный каталог папок, текущая закладка, поиск и общий несохранённый выбор.
Имена/состав папок перечитываются при явном обновлении каталога. В SQLite
сохраняются только выбранные ID, а текущая закладка и поиск не переживают
перезагрузку страницы. Код и 2FA не являются постоянными настройками.
Дедупликация request ID действует 15 минут одного процесса и не переживает рестарт.

Курсор и открытые страницы живут только в памяти браузера. При прокрутке старые
сообщения автоматически читаются из SQLite; переход к другому адресату открывает
его свежую страницу. Автообновление сохраняет уже открытые старые страницы.
В settings хранятся read.position.<conversationId> с датой, ID и sequence
просмотренного сообщения, discovery.baseline.<sourceId> с исходной отметкой
и временный discovery.notify.<conversationId> для первой свежей головы нового контакта.
Позиция просмотра сохраняется только после успеха источника, не двигается назад
и защищает счётчик от старых метаданных. Telegram sequence различает сообщения
одной секунды; прежние составные ID поддерживаются без повторного чтения истории.
Первичная синхронизация большой истории требует времени и места на диске;
открытие уже сохранённых сообщений не ждёт Telegram.

## Расшифровки голосовых

Таблица `voice_transcriptions` хранит текст, pending, ID задания источника,
ID вложения, версию сообщения и время обновления. Она находится в той же
приватной SQLite личного аккаунта, отдельно от исходного message_cache:
синхронизация Telegram не стирает результат. В Message выдаются только text/pending,
если ID и версия всё ещё относятся к доступному голосовому. При удалении
сообщения расшифровка удаляется; при исключении диалога архив сохраняется,
но не выдаётся через API. Команда очистки кеша удаляет и расшифровки.

## Байты вложений

Attachment содержит общий ID, kind image/video/audio/file/unsupported, имя,
необязательные mimeType/size, downloadable и hasPreview. В SQLite остаются только эти
метаданные. Скачанные байты лежат отдельно в attachments/ с правами 0700/0600,
не шифруются и не входят в релиз/Git. Ключ кеша включает источник, диалог,
сообщение, вложение, дату правки и вариант preview для миниатюры.
Оригинальный ключ прежней версии сохраняется. У миниатюр есть приватный .bin.json
с безопасным дескриптором; отсутствие превью запоминается отдельной отметкой.
Заготовки .part заменяются атомарно только
после полного чтения; незавершённые файлы убираются при ошибке и старте процесса.

LRU ограничен 512 МиБ и 2048 записями (оригинал, миниатюра или отметка её отсутствия).
Ограничение миниатюры — 512 КиБ. Текущие ответы защищены от вытеснения;
одновременно загружаются не более двух файлов по 32 МиБ. Временный объём может
превысить бюджет на эти две загрузки. Исключение диалога оставляет имеющиеся
байты, но закрывает доступ; обычное вытеснение медиа не удаляет текстовый архив.
Повторное открытие готового файла не обращается к Telegram. cache:clear очищает
и SQLite-кеш, и байты вложений; перед этой командой сервер следует остановить.

MediaPreloadService читает индексированный диапазон date за последние 5 дней,
соединяет его с selected_conversations и JSON-метаданными вложений. За один проход
выбирает до 20 кандидатов и загружает не более одного файла. Завершение оригинала
и миниатюры отмечается независимо по версии сообщения; временный отказ повторяется
не раньше минуты. FloodWait сохраняет общую паузу медиа в settings;
она переживает рестарт, а активная пауза текстовой синхронизации также соблюдается.
Исключение чата закрывает выборку, повторное включение использует
имеющийся кеш. Служебные отметки старше окна удаляются, сообщения и байты — нет.
После вытеснения завершённое фоновое задание не перекачивает файл циклически: повтор
происходит по пользовательскому запросу. Новые и отредактированные версии получают
свои задания. cache:clear очищает также отметки фоновой подготовки.

Браузер хранит до 32 Blob миниатюр (не более 16 МиБ) только в оперативной памяти.
IntersectionObserver загружает превью возле видимой области по одному; отдельный
оригинал появляется лишь в окне просмотра. Object URL отзывается при уходе превью
с экрана или закрытии окна. Выход, исключение диалога и reset очищают память превью.
Сохранение пользователем отдельно передаёт файл штатным средствам браузера.

## Постоянный вход чата

`auth.sessions` в приватной SQLite содержит только SHA-256 digest chat-токенов,
CSRF, срок и отпечаток версии пароля. Исходные cookie не записываются. Вход
сохраняется при рестарте, действует 180 дней и продлевается при использовании.
Выход, блокировка и смена пароля отзывают доступ с сохранением отзыва на диске.
Административные сессии остаются в памяти и действуют восемь часов.
Локальное чтение без сети по-прежнему ограничено восемью часами с последнего
подтверждения, независимо от длительного серверного входа.

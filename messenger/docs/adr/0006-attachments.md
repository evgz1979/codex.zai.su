# ADR-0006: вложения по запросу через защищённый backend

Статус: принято по заданию владельца о просмотре вложений. Дата: 2026-11-07.

Дополнено в 0.7.0: [ADR-0007](0007-media-preload.md) заменяет режим только по
нажатию, бюджет кеша и способ открытия документов. Ниже — решение первого выпуска.

## Решение

SourceAdapter получает необязательный openAttachment: общий Attachment и
AsyncIterable байтов. TelegramAdapter повторно получает одно сообщение нужного
peer; native file references остаются внутри коннектора. Общая модель и единая
лента не зависят от Telegram API.

POST /api/chat/attachment требует chat-сессию, Origin и CSRF. Ядро сверяет
сохранённый маршрут; разрешение проверяется до кеша, во время загрузки и ответа.
Байты накапливаются потоком в приватном файле, а не одним Buffer в памяти Node.
Частичный файл становится готовым только после полной загрузки и проверки.
Кеш ограничен 256 МиБ/256 файлами, одно вложение — 32 МиБ, параллелизм — два.
Это бюджет начального выпуска для существующего VPS без отдельного медиасервиса.

Браузер по нажатию получает Blob и показывает фото либо нативный video/audio.
Документы доступны для скачивания; собственный PDF-движок и транскодирование
не добавляются. Закрытие отменяет запрос и отзывает object URL. Фоновая
синхронизация истории сохраняет только метаданные вложений.

## Последствия

Повторное открытие использует кеш, старые placeholder-сообщения уточняются
точечным запросом без повторного обхода истории. Исключение диалога закрывает
доступ, не очищая его архив. Вытеснение бинарного кеша не удаляет текстовую историю.
Самоуничтожающиеся и неподдерживаемые объекты остаются в официальном Telegram.
Поддержка кодека определяется браузером, скачивание служит доступным действием.
Нет новых сервисов, внешних ресурсов, публичных путей к файлам и доступа медиа к ИИ.

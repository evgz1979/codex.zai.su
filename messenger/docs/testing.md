# Проверки

## Команды

```bash
bash messenger/scripts/npm.sh test
bash messenger/scripts/npm.sh run build
bash messenger/scripts/npm.sh exec -- playwright install chromium webkit
bash messenger/scripts/npm.sh run test:browser
bash messenger/scripts/npm.sh run docs:build
bash messenger/scripts/npm.sh run docs:check
bash messenger/scripts/npm.sh run docs:test
```

Core/HTTP-тесты проверяют межисточниковые коллизии, общую ленту, маршрут отправки,
дедупликацию, границы кеша, права файлов, шифрование, Argon2id, отзыв сессий, rate limit,
Host, Origin, CSRF и отсутствие исходных исключений в API. Браузерные сценарии:
Chromium desktop, WebKit iPhone 13 и iPhone SE, вход/выход, общая лента из двух
синтетических источников, смена адресата и черновика, отправка, непрочитанные,
обновление, отсутствие горизонтального скролла и доступность composer при малой высоте.
Тестовые серверы используют только `127.0.0.1:14318`, `:14319` и `:14320`, временные
БД и фиктивные пароли. Скриншоты — в игнорируемом `messenger/test-results/`.
Физический iPhone/Safari и операции реальной Telegram-сессии проверяются отдельно
от синтетических тестов; фактически проверенные операции перечислены в протоколе.

## Ручная проверка владельцем

После [авторизации через админку](telegram.md) проверить загрузку личного диалога и
группы, счётчики, выбор адресата и отправку себе в «Избранное»; сверить результат
в официальном Telegram. Перед повтором неизвестной отправки дождаться сверки и проверить Telegram.
Затем перезапустить сервер: веб-вход повторяется, код Telegram запрашиваться
не должен, фон автоматически продолжает сохранённые курсоры.

Физический iPhone проверяется через https://msg.zai.su:8443/ после развёртывания.
Эмуляция WebKit сама по себе не проверяет мобильного оператора, Safari chrome
и настоящую экранную клавиатуру. Реальный аккаунт подключает только владелец.

## Границы воспроизводимости

Для server/HTTP и browser нужны разрешённые локальные TCP-порты и установленные
браузерные движки. `docs:check` и `docs:test` работают без сети и серверов.
Исходники функции и две строки пояснения проверяются AST; изменение только
пустых строк или обычных комментариев не должно менять ни одной страницы.
В документационных тестах используются временные копии разрешённых исходников
и docs, без `.local/`, пользовательских Telegram-сессий и БД.

## Дополнения сценариев по версиям

Числа ниже относятся к соответствующему срезу. Полный текущий набор имён
строится из исходников в reference/tests.md; результаты запусков, даты и
границы проверок находятся в validation.md.

### Версия 0.2.0

14 server-тестов включают пустой выбор, отказ невыбранным ID, ревизию при снятии
галочки во время чтения, сохранение выбора и архива, code/2FA/cancel с fake MTProto,
Secure/HttpOnly/SameSite/Path cookie, CSRF и независимость прав admin/chat.
Два браузерных сценария запускаются в трёх конфигурациях (6 запусков): чат и
отдельная админка с синтетическими Telegram-этапами. Реальный Telegram не вызывается.
Дополнительный desktop-сценарий проверяет скрытие исключённых ID в открытом чате.
Три Python-теста guard проверяют точный upstream/host и сохранение запрета 443,
публичного 8080 и TLS-ALPN-01. Исходные шесть тестов guard HTTPS также сохраняются.

Развёртывание выполняет эти проверки автоматически, затем проверяет health,
страницы / и /admin, 401 закрытых API, неизменность Codex-site и VPN-снимков.
Наличие auto-restart/systemd enable проверяется на VPS; reboot сервера ради теста
не выполняется, чтобы не нарушать работающий VPN.

### Версия 0.2.1

Дополнительные auth-сценарии вызывают `signInUser` установленной teleproto с
подменой только сетевого invoke и проверки 2FA. Так проверяется сохранение
первоначального отказа до преобразования библиотеки в AUTH_USER_CANCEL,
повтор неверного кода без нового SendCode и завершение после пяти проверок.
Реальный Telegram и реальные ключи в этих тестах не используются.
UI-причина начального отказа проверяется в Chromium и двух конфигурациях WebKit.

### Версия 0.3.0

Папки проверяются на синтетических TL-объектах teleproto: explicit include/exclude,
приоритет исключения, закрепления, shared folder, контакты/боты/группы/каналы,
непрочитанные и пометка unread, архив, mute со сроком и глобальным наследованием,
исключение для упоминаний. Выбор папки не даёт прав чтения или отправки.
Повторное создание адаптера использует сохранённую сессию без logOut/start.
Браузеры проверяют настоящие role=tab/tabpanel, порядок закреплений, пересечения,
сохранение скрытых галочек, поиск, пустую папку, клавиатуру, исчезнувшую папку
после обновления и отсутствие горизонтального скролла страницы на iPhone.
Скриншоты используют только синтетические имена и остаются вне Git.

### Версия 0.4.0

HTTP-тест принимает новый пароль из 8 символов и отклоняет 7. Браузер проверяет
тот же минимум формы. Страницы проверяются отдельно от общей ленты: старый
адресат получает свои 10, даже когда в общем снимке только более новые сообщения
другого чата. Проверены конец истории, сервисные записи, курсор чужого диалога,
отзыв/возврат доступа во время RPC и отметка прочитанного при полном общем кеше.
Во всех браузерных конфигурациях проверяются быстрый переход с незавершённого
запроса, 10 + 10 + 5, сохранение прокрутки и отсутствие автоматической догрузки.

### Версия 0.5.0

Полный кеш проверяется на синтетической истории больше прежних 40 записей:
возобновление курсора, пропуск больше страницы после отключения, новое событие
до закрытия пропуска, правки/удаления, FloodWait, снятие выбора во время запроса
и восстановление после усечения старой версией. Открытие/прокрутка работают при
недоступном источнике и не увеличивают число MTProto-запросов. Браузер проверяет
автопрокрутку, появление и удаление сообщений по ревизии без кнопок загрузки.

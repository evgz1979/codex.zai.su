# Сквозные сценарии

## Первоначальная установка

MacBook генерирует два случайных пароля вне Git → SSH передаёт только Argon2id-хеши
в CLI bootstrap → SQLite создаёт настройки ролей → production-сервер проверяет
их готовность → локальный healthz → только затем Caddy публикует сайт.
Повторная установка сохраняет текущие реквизиты и данные.

## Административный вход и Telegram

/admin → admin/session → admin/login → отдельная Secure cookie и CSRF.
Telegram begin проверяет формат ключей и телефона, создаёт приватный teleproto-клиент.
При запросе кода появляется одноразовый resolver → code передаёт значение клиенту.
Если нужен 2FA, password передаёт значение второму resolver. После успешной проверки
в vault записывается сессия с accountId. Ответ содержит только stage. Значения кода
и 2FA не записываются, фабрика клиента отключает журналы библиотеки.

При отказе status возвращает только TelegramAuthIssue из разрешённых категорий.
Причина сохраняется до преобразования ошибки библиотекой в AUTH_USER_CANCEL.
Неверный код или 2FA возвращают тот же ожидающий шаг; новый SendCode не запускается.
Отказ при выполненных пяти или более проверках кода/2FA завершает процесс;
пять минут ожидания также завершают вход. Остальные отказы сразу переводят его
в error. Отмена очищает безопасную причину; рестарт процесса
не сохраняет незавершённый вход. Подробности — в [руководстве Telegram](telegram.md).

## Разрешение и исключение диалогов

admin/dialogs → Telegram listConversationCatalog → метаданные GetDialogs и
GetDialogFilters → правила папок → ConversationCatalog, preview отбрасывается.
При excludeMuted дополнительно читаются глобальные настройки звука трёх категорий;
этот запрос не включает уведомления Messenger и не меняет настройки Telegram.

Выбор закладки → локальный фильтр conversationIds → поиск по названию → таблица.
Общие ID связывают галочки пересекающихся папок. Переключение не отправляет запрос
выбора; сохранение включает скрытые другими закладками отмеченные диалоги.

Галочки → admin/selection → проверка известного каталога → транзакция SQLite →
увеличение ревизии → reset снимка из выбранного кеша. Нет фонового обхода остальных
диалогов. При исключении данные остаются, но перестают участвовать в UI и sync.
Открытая вкладка получает разрешённые ID, ревизию и ID удалений каждые 2 секунды
и при возвращении на вкладку. Исключённые диалоги немедленно скрываются при ответе.
Опрос читает только серверный кеш.

## Автоматическая история и пользовательская лента

После выбора диалогов AutoSyncService получает метаданные и свежие страницы,
подписывается на события новых сообщений, правок и удалений. Далее последовательно
заполняет всю доступную историю, чередуя старые страницы со сверкой свежих.
Пропуск после разрыва связи догружается до пересечения с предыдущей проверенной
головой, даже если новые события уже успели попасть в кеш. FloodWait приостанавливает
запросы на требуемый срок. Выход из браузера не останавливает синхронизацию.

/ → chat/login → chat/inbox → SQLite → общая хронология. Выбор адресата → chat/open
→ его свежая страница SQLite. Никакой Telegram RPC не входит в эти операции.
Прокрутка вверх → chat/older либо chat/inbox с курсором → предыдущие 10 из SQLite.
При незавершённой фоновой загрузке UI ждёт следующей ревизии, не зацикливая запросы.
Положение прокрутки сохраняется; поздний ответ прежнего адресата отбрасывается.
Опрос access запускает перечитывание свежей части при изменении ревизии, сохраняя
открытую старую историю. Удаления убираются по общим ID. Чужие черновики не переносятся.
Явная отметка прочитанного остаётся отдельным действием; просмотр не сбрасывает счётчик.

## Отправка

Форма фиксирует Destination и requestId → сервер проверяет selection, модель и
canSend → коннектор сверяет source/recipient с native peer → буквальная отправка.
Успех добавляет Message и очищает только этот черновик. Неизвестный результат
блокирует повтор до завершения автоматической сверки свежих сообщений. Дедупликация request ID живёт до
15 минут одного процесса; перезапуск не доказывает отсутствие отправки.
Уже начатую Telegram-операцию нельзя отозвать последующим изменением галочки.

## Выход, отключение, обновление

Выход роли отзывает только её веб-сессию. Отключение Telegram отдельно пытается
отозвать удалённый доступ, удаляет локальную сессию, снимает выбор, оставляет архив.
Остановка процесса закрывает адаптеры, незаконченный вход и SQLite. После рестарта
нужен веб-вход; Telegram использует серверную сессию, выбор восстанавливается из SQLite.
Релиз переключает только кодовый symlink; приватный каталог не заменяется.

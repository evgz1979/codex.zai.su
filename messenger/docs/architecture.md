# Архитектура

```text
/      → Chat App  → /api/chat/*  → MessengerService (MessengerCore)
/admin → AdminApp → /api/admin/* → AdminService
                                  ↓
          ConversationSelectionService ↔ SQLite
                    ↓
              UnifiedInboxService
                    ↓
              ConnectorRegistry → TelegramAdapter → MTProto
                                        ↓
                                   SecretVault
```

Один Node.js-процесс, React и встроенный SQLite. У пользовательского и
административного интерфейсов отдельные компоненты, компоновки и API.
Источник выбирается только в админке. В пользовательской части одна лента,
один адресат и одно поле ввода, без административной навигации и вкладок сервисов.

| Компонент | Ответственность |
| --- | --- |
| MessengerService | Общее ядро операций, лимиты, маршрутизация и дедупликация |
| SourceAdapter | Провайдерный контракт; только общие DTO |
| ConversationCatalog / ConversationFolder | Метаданные и папки источника, без прав на чтение истории |
| TelegramAdapter | Native Telegram peer и преобразование сообщений |
| ConnectorRegistry | Реестр подключённых источников |
| AdminService | Настройки, каталог метаданных, отключение и пароли |
| ConversationSelectionService | Постоянный выбор и серверный контроль доступа |
| UnifiedInboxService | Финальная фильтрация всех ответов ленты |

## Каталог папок

Необязательный SourceAdapter.listConversationCatalog возвращает общий каталог
с ConversationFolder. Для источника без этой возможности админка использует
listConversations и пустой массив папок. TelegramAdapter читает собственные
dialog filters и преобразует их в общие ID; native peer и access_hash остаются
на сервере. Обычный refresh общей ленты не запрашивает правила папок.

ConversationPicker живёт только внутри AdminApp: локальная закладка и поисковая
строка фильтруют таблицу, а selected содержит общий выбор. После нажатия
«Сохранить выбор» AdminService проверяет ID всего каталога и обновляет SQLite.
Папка не становится отдельным разрешением или отдельной перепиской.

Сейчас рабочий коннектор только Telegram. Будущие WhatsApp, Codex и Email
добавляются адаптерами и административными настройками; пустых реализаций нет.
Код существующего Codex-клиента вне messenger не используется и не переносится.
Telegram-сообщения не становятся контекстом Codex/ChatGPT.

## Ограничения выборок

Метаданные: до 1000 Telegram dialogs, включая читаемые каналы. Выбор: до 100.
Refresh читает только метаданные и непрочитанные. Открытие адресата читает до 10
последних сообщений, older — предыдущую страницу до 10. Активная страница
возвращается отдельно от общего кеша: старый диалог не вытесняется новыми
сообщениями другого адресата. Общая лента показывает 10 последних уже загруженных
сообщений разных источников; её серверный кеш ограничен 400, SQLite — 40 на диалог.
История других чатов не загружается при открытии или обновлении адресата.
При смене выбора ревизия позволяет отбросить старый результат незаконченного чтения.
Медиа, секретные чаты, уведомления, звонки и полная история не поддерживаются.

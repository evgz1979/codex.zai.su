# Codex Z AI

Самостоятельный проект `/Users/evgz/Documents/codex.zai.su`. Не связан с Actu и
lighnode. Общение с пользователем и документация — на русском языке.

## Ограничения

- Серверы самого приложения слушают только `127.0.0.1`. Не публиковать приложение
  без отдельного задания. Не менять VPN.
- В задании №2 разрешён только статический HTTPS-тест на `38.60.254.194:8443`
  для `codex.zai.su`. Внешний TCP 80 нужен только для ACME HTTP-01 и передаётся
  через отдельный socket systemd на `127.0.0.1:8080`. Caddy работает без root
  и capabilities. Шаблоны и инструкции — `deploy/https-test/`.
- TCP 443 принадлежит Xray/VLESS REALITY. Не занимать его даже временно,
  не менять конфигурацию/порт VPN, не останавливать и не перезапускать x-ui/Xray.
  Не менять sysctl или firewall ради теста. При риске для VPN остановиться.
- TLS-ALPN-01 выключен. При недоступности HTTP-01 предложить DNS-01 и ждать
  отдельного согласования. Реальный веб-клиент и App Server не развёртывать.
- Перед изменениями на VPS и после них сравнивать снимки PID, времени запуска,
  состояния VPN, хешей конфигурации и firewall через `vpn_snapshot.py`.
  Приватные снимки сохранять только в `.local/` или отдельной папке VPS.
- По отдельному запросу пользователя разрешён приватный независимый учёт трафика
  vnStat на eth1: `deploy/traffic/`. Это отдельный сервис без новых портов,
  без изменения VPN, firewall, маршрутов и sysctl. БД и начальные отметки панели
  остаются вне Git. Не публиковать статистику и не создавать напоминания без запроса.
- Codex запускается только через официальный App Server по stdio. Браузер не
  получает прямого доступа к нему, токенам или произвольным RPC-методам.
- Сохранять read-only sandbox и запрет сети для команд. Не использовать `--yolo`,
  `danger-full-access` или автоматическое одобрение запросов разрешений.
- Не добавлять универсальные HTTP-эндпоинты для shell-команд или передачи RPC.
- Не читать и не выводить содержимое файлов авторизации. Пользоваться существующим
  входом `codex login`; не копировать его в проект.
- `.local`, `.tools`, `.env`, истории, БД и логи не коммитить.
- Не подменять ответы Codex фиктивными данными. Тесты reducer/store не являются
  проверкой реального подключения; для него есть `test:live`.
- Не перезаписывать изменения пользователя. Не выполнять force push.

## Разработка

- React + TypeScript + Vite в `frontend`, Node.js + TypeScript в `backend`.
- Backend без runtime-зависимостей, общие DTO в `shared`.
- Целевая среда — Node.js 22 (не ниже 22.16), Ubuntu 24.04, 1 vCPU / 2 ГБ RAM.
- Источник истины для истории — Codex. Локальный JSON хранит только индекс
  диалогов этого приложения. Не открывать через API посторонние сессии Codex.
- Проверки: `bash scripts/npm.sh test`, `bash scripts/npm.sh run build`.
- Для HTTPS-теста: `python3 -m unittest discover -s deploy/https-test -p 'test_*.py' -v`;
  реальную конфигурацию обязательно проверять Caddy adapt и штатным guard.
- Для счётчика: `python3 -m unittest discover -s deploy/traffic -p 'test_*.py' -v`;
  проверять реальные приращения TX и сохранение истории при рестарте только счётчика.
- Live-проверка: запущенный backend, `bash scripts/npm.sh run test:live`,
  перезапуск backend, `bash scripts/npm.sh run test:live -- resume`.
- Изменения протокола сверять с https://learn.chatgpt.com/docs/app-server и
  схемами `codex app-server generate-ts --out /tmp/codex-zai-protocol`.
- Персональная память — отдельный будущий этап; точка расширения `memory.ts`.
